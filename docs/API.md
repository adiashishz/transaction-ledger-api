# API reference

- **Base URL:** `http://localhost:8000/api`
- **Format:** requests and responses are JSON. Send `Content-Type: application/json`.
- **Authentication:** none.
- **Interactive docs:** Swagger UI at `/api/docs`, OpenAPI 3 schema at `/api/schema`.

## Endpoints

| Method | Path | Description |
|---|---|---|
| `POST` | [`/accounts`](#create-an-account) | Create an account |
| `GET` | [`/accounts`](#list-accounts) | List accounts (paginated) |
| `GET` | [`/accounts/{account_id}`](#get-an-account) | Get an account |
| `GET` | [`/accounts/{account_id}/balance`](#get-a-balance) | Get an account's balance |
| `POST` | [`/accounts/{account_id}/transactions`](#add-a-transaction) | Add a credit or debit |
| `GET` | [`/accounts/{account_id}/transactions`](#transaction-history) | Transaction history (filter + pagination) |
| `POST` | [`/transfers`](#transfer-between-accounts) | Transfer money between two accounts |

Transactions and transfers have no update or delete endpoints. They are immutable.

## Conventions

- **IDs** are UUIDs generated by the server.
- **Money** is returned as a string with two decimals, for example `"150.00"`, so no precision is lost in transit.
  - Send `amount` as a JSON number (`150.5`) or a plain decimal string (`"150.50"`).
  - It must be greater than 0, with at most 2 decimal places, and no more than `9,999,999,999.99`.
  - Strings such as `"1e2"`, `"+5"` or `" 7 "` are rejected.
- **Timestamps** are ISO 8601 in UTC, for example `"2026-10-28T12:35:29.459155Z"`.
- **Unknown fields** in a request body are rejected with `400`. Unknown query parameters are ignored.

## Errors

Every error uses the same shape:

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Insufficient funds.",
    "details": { "balance": "379.50", "requested": "1000.00", "shortfall": "620.50" }
  }
}
```

- `code` is stable and meant for programs to check.
- `message` is meant for people to read.
- `details` is always an object. For validation errors it maps each field to a list of messages.

| HTTP | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | A body or query field is missing or invalid, there's an unknown field, or the body isn't an object |
| 400 | `MALFORMED_JSON` | The body isn't valid JSON |
| 400 | `INVALID_ACCOUNT_ID` | The account ID in the URL isn't a UUID |
| 404 | `ACCOUNT_NOT_FOUND` | No account has that ID |
| 404 | `NOT_FOUND` | Unknown URL |
| 405 | `METHOD_NOT_ALLOWED` | The method isn't supported, for example `DELETE` on transactions |
| 406 | `NOT_ACCEPTABLE` | The client doesn't accept JSON |
| 409 | `DUPLICATE_TRANSACTION` | The `reference_id` is already used on this account. `details.transaction` holds the original |
| 409 | `DUPLICATE_TRANSFER` | The source account already made a transfer with this `reference_id`. `details.transfer` holds the original |
| 413 | `PAYLOAD_TOO_LARGE` | The request body is larger than 2.5 MB |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | The body isn't `application/json` |
| 422 | `INSUFFICIENT_BALANCE` | A debit or transfer is larger than the balance |
| 422 | `BALANCE_LIMIT_EXCEEDED` | A credit would push the balance past the maximum the ledger can store |
| 500 | `INTERNAL_ERROR` | Unexpected server error. Details are logged, never returned |

Checks run in this order: URL ID, then request body or query, then whether the account exists, then duplicate, then balance. So a retried debit that already succeeded gets `409`, not `422`.

## Pagination

List endpoints accept `page` (default 1, at least 1) and `limit` (default 10, from 1 to 100). Invalid values return `400`; they are never adjusted silently. A page past the end returns an empty `data` list.

```json
{
  "data": [ ... ],
  "pagination": { "page": 1, "limit": 10, "total_records": 31, "total_pages": 4 }
}
```

## Create an account

`POST /accounts`

| Field | Type | Required | Rules |
|---|---|---|---|
| `name` | string | yes | 1–255 characters after trimming whitespace |

The balance always starts at `0.00`. The client can't set `balance`, `id` or `created_at`.

```json
{ "name": "Kavya Nair" }
```

`201 Created`

```json
{
  "id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
  "name": "Kavya Nair",
  "balance": "0.00",
  "created_at": "2026-10-28T12:35:29.358277Z"
}
```

Errors: `400 VALIDATION_ERROR`, `400 MALFORMED_JSON`, `415`. For example, sending a balance:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed.",
    "details": { "balance": ["balance cannot be set; new accounts always start at 0."] }
  }
}
```

## List accounts

`GET /accounts?page=1&limit=2`

Returns accounts, newest first.

**Why it was added (not in the brief):** with only the brief's endpoints, the create response is the only place an account's ID ever appears. A client that didn't store it, or someone exploring the API, has no way to find an account again. The list is paginated like the history endpoint, so it stays cheap as the number of accounts grows. A real deployment would restrict it to administrators, because it shows every account.

`200 OK`

```json
{
  "data": [
    { "id": "924412b9-19a1-4f89-a116-8f6fc413ccac", "name": "Kavya Nair", "balance": "0.00", "created_at": "2026-10-28T12:35:29.358277Z" },
    { "id": "00000000-0000-4000-8000-000000000004", "name": "Ananya Iyer", "balance": "950.00", "created_at": "2026-10-28T12:33:31.014505Z" }
  ],
  "pagination": { "page": 1, "limit": 2, "total_records": 5, "total_pages": 3 }
}
```

Errors: `400 VALIDATION_ERROR` (invalid `page` or `limit`).

## Get an account

`GET /accounts/{account_id}`

Returns the full account: `id`, `name`, `balance` and `created_at`.

**Why it was added (not in the brief):** the brief's balance endpoint returns only `account_id` and `balance`, so after an account is created there's no way to read its `name` or `created_at` again. That's what a client needs to confirm *whose* account an ID belongs to, for example before transferring money to it. The balance endpoint stays as the brief specifies, as the small response for quick balance checks.

`200 OK`

```json
{
  "id": "00000000-0000-4000-8000-000000000001",
  "name": "Aarav Sharma",
  "balance": "100.00",
  "created_at": "2026-10-28T12:33:31.008516Z"
}
```

Errors: `400 INVALID_ACCOUNT_ID`, `404 ACCOUNT_NOT_FOUND`.

```json
{
  "error": {
    "code": "ACCOUNT_NOT_FOUND",
    "message": "Account not found.",
    "details": { "account_id": "00000000-0000-4000-8000-000000000999" }
  }
}
```

## Get a balance

`GET /accounts/{account_id}/balance`

`200 OK`

```json
{
  "account_id": "00000000-0000-4000-8000-000000000001",
  "balance": "100.00"
}
```

Errors: `400 INVALID_ACCOUNT_ID`, `404 ACCOUNT_NOT_FOUND`.

## Add a transaction

`POST /accounts/{account_id}/transactions`

| Field | Type | Required | Rules |
|---|---|---|---|
| `type` | string | yes | `credit` or `debit` (lowercase) |
| `amount` | number or string | yes | See [Conventions](#conventions) |
| `reference_id` | string | yes | 1–100 characters after trimming. Unique per account; case-sensitive |
| `description` | string | no | Up to 255 characters. Defaults to `""` |

`account_id` comes from the URL. Sending it in the body is rejected.

- A **credit** adds to the balance.
- A **debit** subtracts from it, and is rejected if the balance is too low.
- Saving the transaction and updating the balance happen in one atomic operation.

**About `reference_id`:** the client makes it up, usually from its own order or invoice number, and resends the same value when it retries. Sending a `reference_id` that already exists on the account changes nothing and returns `409` with the original transaction, so a retry can never post twice. A request rejected with `400`, `404` or `422` stores nothing, so its `reference_id` can be used again.

```json
{ "type": "credit", "amount": "500.00", "reference_id": "INV-1001", "description": "Invoice 1001" }
```

`201 Created`

```json
{
  "id": "e70fb141-bfab-4de0-a405-ab9da4d7b979",
  "account_id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
  "type": "credit",
  "amount": "500.00",
  "description": "Invoice 1001",
  "reference_id": "INV-1001",
  "transfer_id": null,
  "created_at": "2026-10-28T12:35:29.459155Z"
}
```

`transfer_id` is set only when the transaction is one leg of a transfer.

Errors:

| HTTP | `code` | Example `details` |
|---|---|---|
| 400 | `VALIDATION_ERROR` | `{"type": ["\"refund\" is not a valid choice."], "amount": ["Amount must be greater than 0."], "reference_id": ["This field may not be blank."]}` |
| 400 | `INVALID_ACCOUNT_ID` | `{"account_id": "not-a-uuid"}` |
| 404 | `ACCOUNT_NOT_FOUND` | `{"account_id": "…"}` |
| 409 | `DUPLICATE_TRANSACTION` | `{"transaction": { …the original transaction… }}` |
| 422 | `INSUFFICIENT_BALANCE` | `{"balance": "379.50", "requested": "1000.00", "shortfall": "620.50"}` |
| 422 | `BALANCE_LIMIT_EXCEEDED` | `{"balance": "…", "requested": "…", "max_balance": "9999999999999999.99"}` |

A duplicate looks like this:

```json
{
  "error": {
    "code": "DUPLICATE_TRANSACTION",
    "message": "A transaction with reference_id 'INV-1001' already exists for this account.",
    "details": {
      "transaction": {
        "id": "e70fb141-bfab-4de0-a405-ab9da4d7b979",
        "account_id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
        "type": "credit",
        "amount": "500.00",
        "description": "Invoice 1001",
        "reference_id": "INV-1001",
        "transfer_id": null,
        "created_at": "2026-10-28T12:35:29.459155Z"
      }
    }
  }
}
```

## Transaction history

`GET /accounts/{account_id}/transactions`

| Query parameter | Default | Rules |
|---|---|---|
| `type` | both | `credit` or `debit` |
| `page` | 1 | Integer, at least 1 |
| `limit` | 10 | Integer from 1 to 100 |

Results are sorted newest first by `created_at`. If two transactions have the same timestamp, `id` decides the order, so pages stay stable.

`GET /accounts/00000000-0000-4000-8000-000000000001/transactions?type=debit&page=1&limit=2`, `200 OK`:

```json
{
  "data": [
    {
      "id": "d2db1ee7-afed-412a-bd1b-97a41c1802fc",
      "account_id": "00000000-0000-4000-8000-000000000001",
      "type": "debit",
      "amount": "20.00",
      "description": "Electricity bill",
      "reference_id": "SEED-004",
      "transfer_id": null,
      "created_at": "2026-10-28T12:33:31.035568Z"
    },
    {
      "id": "c994d296-bbec-4ebf-9a56-858b2722cdc5",
      "account_id": "00000000-0000-4000-8000-000000000001",
      "type": "debit",
      "amount": "30.00",
      "description": "Groceries",
      "reference_id": "SEED-003",
      "transfer_id": null,
      "created_at": "2026-10-28T12:33:31.030627Z"
    }
  ],
  "pagination": { "page": 1, "limit": 2, "total_records": 2, "total_pages": 1 }
}
```

Errors: `400 INVALID_ACCOUNT_ID`, `400 VALIDATION_ERROR` (for example `{"page": ["Ensure this value is greater than or equal to 1."]}`), `404 ACCOUNT_NOT_FOUND`.

## Transfer between accounts

`POST /transfers`

| Field | Type | Required | Rules |
|---|---|---|---|
| `from_account_id` | string (UUID) | yes | Must exist |
| `to_account_id` | string (UUID) | yes | Must exist and differ from `from_account_id` |
| `amount` | number or string | yes | See [Conventions](#conventions) |
| `reference_id` | string | yes | 1–100 characters. Unique per source account, and not already used on either account |
| `description` | string | no | Used for both legs. Defaults to "Transfer to {name}" and "Transfer from {name}" |

A transfer creates a debit on the source and a credit on the destination. Both legs and both balance updates are saved in one atomic operation: either all of it happens or none of it does. Each leg is an ordinary transaction that shows up in that account's history, with `transfer_id` set.

```json
{
  "from_account_id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
  "to_account_id": "00000000-0000-4000-8000-000000000003",
  "amount": "100.00",
  "reference_id": "TRF-3001",
  "description": "Lunch split"
}
```

`201 Created`

```json
{
  "id": "cb54f7ab-feae-4386-8443-adf0e92d6b91",
  "from_account_id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
  "to_account_id": "00000000-0000-4000-8000-000000000003",
  "amount": "100.00",
  "description": "Lunch split",
  "reference_id": "TRF-3001",
  "created_at": "2026-10-28T12:35:29.587173Z",
  "debit_transaction": {
    "id": "d4239199-a219-482f-b26e-3ff0935e7fc2",
    "account_id": "924412b9-19a1-4f89-a116-8f6fc413ccac",
    "type": "debit",
    "amount": "100.00",
    "description": "Lunch split",
    "reference_id": "TRF-3001",
    "transfer_id": "cb54f7ab-feae-4386-8443-adf0e92d6b91",
    "created_at": "2026-10-28T12:35:29.588412Z"
  },
  "credit_transaction": {
    "id": "e4b075ff-f4e3-418e-ae3e-2b502c25c6fc",
    "account_id": "00000000-0000-4000-8000-000000000003",
    "type": "credit",
    "amount": "100.00",
    "description": "Lunch split",
    "reference_id": "TRF-3001",
    "transfer_id": "cb54f7ab-feae-4386-8443-adf0e92d6b91",
    "created_at": "2026-10-28T12:35:29.589403Z"
  }
}
```

Errors:

| HTTP | `code` | When / example `details` |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Same account: `{"to_account_id": ["Must be different from from_account_id."]}` |
| 404 | `ACCOUNT_NOT_FOUND` | Message "Source account not found." or "Destination account not found.", with `{"field": "to_account_id", "account_id": "…"}` |
| 409 | `DUPLICATE_TRANSFER` | The source already used this `reference_id` for a transfer. `{"transfer": { …the original transfer… }}` |
| 409 | `DUPLICATE_TRANSACTION` | The `reference_id` is already used by a transaction on the source or destination account |
| 422 | `INSUFFICIENT_BALANCE` | The source balance is lower than `amount` |
| 422 | `BALANCE_LIMIT_EXCEEDED` | The destination would go past the maximum balance |
